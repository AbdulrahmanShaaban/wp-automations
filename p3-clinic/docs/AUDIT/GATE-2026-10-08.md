- **C1 (سبب جذري للأداء البطيء)**: bind-mount عبر Docker Desktop (stat 2–64ms/ملف × 490 ملف/request) → عولج بـ`scripts/php-tune.js` (realpath/opcache: `validate_timestamps=0`, `memory=192`, `max_accelerated_files=20000`) الموصول بـ`lifecycleScripts.afterStart` في `.wp-env.json`. بعد الإحماء TTFB ≈ 0.4–0.7s (أول طلبات = تدفئة).

- ceiling الـperformance محكوم بـbind-mount محلي — قياس إنتاجي يتطلب نشرًا (غير مدعوم في بيئة العرض).

## ما تبقّى مقبولًا / أبواب نشر (ولي الأمر)

1. **قبل أي نشر فعلي**: `wp config shuffle-salts` + إعادة تسمية مستخدم `admin` + كلمة مرور قوية (wp-env demo: غير مطلوب).
2. **رؤوس cache للملفات الثابتة** — إعداد خادم النشر (Apache/Nginx)، لا يُنفَّذ داخل wp-env.
3. **حدود performance** — قياس إنتاجي بعد النشر (C1 بيئة التطوير فقط).
4. **n8n الحيّ** — التدفّق يُسلَّم كـworkflow JSON موقّع HMAC ويُختبر على sink محلي؛ التشغيل الحيّ على خادم صاحب المشروع (owner-blocked — نفس نمط P2).
5. **`opcache.validate_timestamps=0`** — بعد أي تعديل PHP: `node scripts/php-tune.js` (يعيد تحميل Apache) وإلا التغييرات غير مرئية.
